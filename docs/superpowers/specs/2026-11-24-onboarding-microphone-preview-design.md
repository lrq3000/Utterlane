# Onboarding microphone preview

**Intent.** Make “Something to say?” a faithful hands-on demo of Utterlane keyboard dictation. Tapping the practice mic should open the actual keyboard recording panel, with a waveform driven by the captured audio, streaming recognized text, microphone status and warnings, live speaker controls, and processing feedback.

**Approaches.** Reuse the existing `RecordingPanel` in the onboarding activity (approved): it shares both the view and its capture metrics with the keyboard and does not need keyboard setup. Invoking the keyboard itself would require Android input-method setup and tie the trial to an editor or system overlay; a replica dialog could drift from the real keyboard UI.

**Journey.** Tap the existing practice mic and start the existing onboarding capture. Display the panel at the bottom of the activity, above the system insets, while keeping “Your words” in the same screen. The waveform finishes capture; the panel stays open while recognition drains. The rolling panel preview shows only newly recognized speech; the practice field still combines its typed text and the trial transcript under the existing field limit. Close the panel on completion or Cancel, returning to editable practice text. After Cancel, a new take becomes available when the previous microphone session releases its resources. Keep existing onboarding microphone permission, recording/retention behavior, and trial limit; do not require an enabled keyboard, an overlay permission, or a separate recorder. Keep panel controls reachable on short displays by allowing the panel to scroll.

**Verification.** Exercise the real onboarding UI and controller on an isolated Android guest with controlled capture events: waveform on actual PCM samples, preview before Stop, processing before the final result, and Cancel followed by another clean trial. Keep the existing real-model onboarding test using the same new waveform stop control. No inference algorithm or external dictation contract changes.
